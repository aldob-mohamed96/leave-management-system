1) نظرة عامة على النظام

النظام منصة لإدارة طلبات الإجازات داخل مديرية التعليم، وفق تسلسل إداري: مديرية → إدارة تعليمية → مدرسة. يتيح تقديم الطلبات، تتبع الأرصدة، الاعتماد متعدد المراحل، طباعة نماذج PDF عربية، وتقارير إحصائية.

3) المستخدمون والأدوار

كل مستخدم مرتبط بـ مؤسسة (مديرية / إدارة / مدرسة)، والأدوار تُطبَّق داخل نطاق هذه المؤسسة.

أ) مستوى المدرسة

الدورماذا يفعل عادةً؟
مدير مدرسةاعتماد أولي لطلبات المدرسة، متابعة الموظفين، التوقيع الإلكتروني
وكيل مدرسةصلاحيات مساعدة على مستوى المدرسة
أخصائيإدارة طلبات وإجراءات الإجازات داخل المدرسة
موظف مدرسةدخول للنظام مرتبط بملف موظف (عرض/متابعة حسب الصلاحية)

ب) مستوى الإدارة التعليمية

الدورماذا يفعل عادةً؟
مسؤول الإجازاتمراجعة الطلبات القادمة من المدارس وإبداء الرأي/الاعتماد حسب المسار
مدير الإدارةالاعتماد النهائي على مستوى الإدارة
كاتب الإدارةأعمال إدارية مساعدة

ج) مستوى المديرية

الدورماذا يفعل عادةً؟

وكيل المديريةإشراف ومتابعة

ملاحظة: يمكن إنشاء حساب دخول لموظف من شاشة الموظفين (دور افتراضي: موظف مدرسة)، مع إمكانية الدخول لاحقًا بالبريد أو رقم التليفون.

4) المميزات الرئيسية

  • تسلسل مؤسسات هرمي: مديرية → إدارة → مدارس.
  • إدارة موظفين مع كود وظيفي، درجة استحقاق، هاتف، وربط اختياري بحساب نظام.
  • أنواع إجازات قابلة للضبط (تخصم من الرصيد / لا تخصم، حد أقصى للطلب…).
  • درجات وظيفية تحدد الاستحقاق السنوي.
  • إجازات رسمية تُستثنى من أيام العمل.
  • أرصدة إجازات سنوية مع خصم/استرداد/ترحيل وسجل معاملات.
  • سير عمل اعتماد متعدد الخطوات حسب إعدادات كل مدرسة/مؤسسة.
  • توقيع إلكتروني لمدير المدرسة على الطلب.
  • طباعة PDF عربي لنموذج الإجازة مع QR/Barcode للتحقق.
  • تقارير وإحصاءات حسب نطاق المؤسسة.
  • صفحة «حسابي» لتغيير الاسم / الإيميل / التليفون / كلمة المرور.
  • إجبار تغيير كلمة المرور عند الحسابات الجديدة عند الحاجة.
  • API جاهز للمصادقة وإدارة الطلبات والموظفين.
  • واجهة عربية كاملة واتجاه RTL.

9) الأمان والحسابات

  • كلمات المرور مشفّرة (Hash) داخل قاعدة البيانات.
  • الدخول مرفوض للحساب غير النشط.
  • صلاحيات الأدوار مقيّدة بنطاق المؤسسة (Teams).
  • يمكن فرض تغيير كلمة المرور عند أول دخول.
  • ملف .env يحتوي أسرار التشغيل ولا يُرفع على Git.
  • التحقق العام من نموذج الإجازة عبر مسار عام للرقم/الرمز المطبوع.

10) النشر والتشغيل

  • الكود على GitHub (مستودع عام/خاص حسب الإعداد).
  • على السيرفر: مجلد المشروع هو مستودع Git مرتبط بالـ remote.
  • للتحديث: سحب الكود ثم composer install و php artisan migrate وتحديث الكاش.
  • سكربت مساعد: scripts/server-deploy.sh
  • Document Root يشير إلى مجلد public/.

خدمات مهمة في الكود: LeaveRequestService، LeaveBalanceService، LeaveRequestPdfService، ReportPdfService، DashboardStatsService.
